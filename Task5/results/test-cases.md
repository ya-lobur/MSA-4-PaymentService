## Corner Cases & Error Scenarios

| Test Name                               | Type        | Components                            | Preconditions                                          | Expected Result                                                       |
|-----------------------------------------|-------------|---------------------------------------|--------------------------------------------------------|-----------------------------------------------------------------------|
| Out-of-Order Event Delivery             | Integration | Orchestrator, Kafka                   | Kafka partitions deliver events out of order           | Events processed correctly using correlation ID and state validation  |
| Duplicate Event Handling                | Integration | Orchestrator, Payment Service         | Same event delivered twice                             | Idempotency key prevents duplicate processing                         |
| Saga State Corruption Recovery          | Integration | Orchestrator, PostgreSQL              | Saga state becomes inconsistent                        | System detects inconsistency, alerts ops, prevents further processing |
| Redis Cache Miss During Fraud Check     | Integration | FraudCheck Service, Redis, PostgreSQL | Cached fraud result expired                            | Fallback to DB, fraud check continues                                 |
| Database Connection Loss                | Integration | Payment Service, PostgreSQL           | DB connection lost during transaction                  | Transaction rolled back, retry triggered, eventual success            |
| Kafka Consumer Lag Spike                | E2E         | All services, Kafka                   | Consumer lag exceeds 100 messages                      | Alert triggered, auto-scaling kicks in, lag reduced                   |
| Network Partition Between Services      | E2E         | Orchestrator, Payment Service         | Network partition occurs                               | Kafka ensures eventual delivery, saga resumes after partition heals   |
| Concurrent Debit Attempts               | Integration | Payment Service, PostgreSQL           | Two sagas attempt to debit same account simultaneously | Optimistic locking prevents race condition, one succeeds, one retries |
| Invalid Merchant Account Format         | Integration | Payment Service                       | Credit attempted with malformed merchant ID            | Validation fails, compensation triggered immediately                  |
| Notification Service Persistent Failure | E2E         | All services                          | Notification service down for extended period          | Payment completes, notification queued for retry, eventual delivery   |

## Test Environment Requirements

- **Testcontainers**: PostgreSQL, Kafka, Redis running in Docker containers
- **Test Data**: Pre-seeded customer accounts, merchant accounts, fraud rules
- **Mocks**: External fraud provider APIs mocked for predictable responses
- **Monitoring**: Test metrics collected (latency, throughput, error rates)
- **Temporal/Camunda**: Test workflow environment with in-memory or test database
